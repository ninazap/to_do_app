# Отчёт о личном вкладе в командный проект

## Моя роль

В рамках командного проекта я выступал в роли **backend-разработчика**, отвечающего за реализацию бизнес-логики и API для работы с сущностью задач (*Task*). Моя зона ответственности охватывала проектирование модели задачи, реализацию CRUD-операций и интеграцию этих компонентов в общее API приложения.

---

## Перечень выполненных задач

В ходе работы над проектом мной были выполнены следующие задачи:

### 1. Реализация модели `Task`
- Разработка файла `app/models/task.py`.
- Описание структуры таблицы `task` с использованием SQLAlchemy:
  - идентификатор задачи;
  - основные поля (название, описание, приоритет, дедлайн и др.);
  - связи с пользователем и категорией.
- Обеспечение корректной работы связей (`ForeignKey`, `relationship`) с другими моделями проекта.
- Участие в синхронизации модели с миграциями Alembic (исправление автонумерации `task_id`, добавление новых полей).

### 2. Реализация CRUD-логики для задач
- Разработка логики работы с задачами в `app/crud/task.py`.
- Реализация операций:
  - создание задачи;
  - получение списка задач и отдельной задачи по идентификатору;
  - обновление данных задачи;
  - удаление задачи.
- Обработка граничных случаев (несуществующая задача, отсутствие прав доступа).

### 3. Реализация API-эндпоинтов для задач
- Разработка маршрутов в `app/api/task.py`.
- Интеграция CRUD-логики с FastAPI.
- Использование Pydantic-схем для валидации входных и выходных данных.
- Обеспечение корректной работы эндпоинтов в рамках общей архитектуры приложения.

### 4. Взаимодействие с командой
- Согласование структуры модели `Task` с другими участниками команды.
- Учет требований со стороны frontend и смежных backend-модулей.
- Участие в обсуждении архитектурных решений и код-ревью.

---

## Использованные технологии и инструменты

В процессе работы лично мной использовались следующие технологии и инструменты:

- **Python**
- **FastAPI** — разработка REST API
- **SQLAlchemy** — описание ORM-моделей и работа с базой данных
- **Pydantic** — схемы данных и валидация
- **Alembic** — миграции базы данных
- **PostgreSQL** — реляционная база данных
- **Docker / Docker Compose** — запуск и тестирование проекта в контейнерах
- **Git** — контроль версий и командная разработка

## Саморефлексия

### Личные достижения
- Успешно реализована полноценная CRUD-функциональность для сущности `Task`.
- Получен практический опыт интеграции ORM-моделей, API-слоя и схем данных в единой архитектуре FastAPI-приложения.
- Улучшено понимание работы миграций Alembic и поддержки совместимости схемы базы данных при командной разработке.
- Внесён вклад в стабильную и расширяемую архитектуру backend-части проекта.

### Возникшие трудности
- Сложности при согласовании структуры модели `Task` с изменяющимися требованиями проекта.
- Необходимость учитывать зависимости между таблицами (пользователи, категории) и корректно обрабатывать связи.
- Работа с уже существующими миграциями и их доработка без нарушения целостности базы данных.

### Общие впечатления от командной работы
Командная работа показалась продуктивной и полезной. Проект позволил получить реальный опыт взаимодействия в распределённой команде, научил учитывать чужой код, договариваться о контракте API и аккуратно встраивать свои изменения в общий репозиторий. Опыт работы в команде из 7 человек помог лучше понять процессы коллективной разработки и ответственность за отдельный модуль в рамках большого проекта.
