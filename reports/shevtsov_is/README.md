# Отчёт о личном вкладе в командный проект

## Моя роль

В рамках командного проекта я выступал в роли **backend-разработчика**, отвечающего за реализацию бизнес-логики и API для работы с сущностью задач (*Task*), а также за настройку инфраструктуры разработки.  
Моя зона ответственности включала проектирование модели задачи, реализацию CRUD-операций, интеграцию API и подготовку контейнеризированной среды разработки с использованием Docker и Poetry.

---

## Реализация модели Task

**Разработан файл `app/models/task.py`**  
**Описана структура таблицы `task` с использованием SQLAlchemy**, включая:
- идентификатор задачи;
- основные поля (название, описание, приоритет, дедлайн и др.);
- связи с пользователем и категорией.

**Обеспечена корректная работа связей**
- использование `ForeignKey`;
- настройка `relationship` с другими моделями проекта.

**Выполнена синхронизация модели с миграциями Alembic**
- исправление автонумерации `task_id`;
- добавление и корректировка новых полей.

---

## Реализация CRUD-логики для задач

**Разработана бизнес-логика работы с задачами в `app/crud/task.py`**

**Реализованы CRUD-операции**
- создание задачи;
- получение списка задач;
- получение задачи по идентификатору;
- обновление данных задачи;
- удаление задачи.

**Обработаны граничные случаи**
- попытка работы с несуществующей задачей;
- отсутствие прав доступа.

---

## Реализация API-эндпоинтов для задач

**Разработаны маршруты в `app/api/task.py`**  
**Интегрирована CRUD-логика с FastAPI**

**Использованы Pydantic-схемы**
- валидация входных данных;
- формирование выходных DTO.

**Обеспечена корректная работа эндпоинтов**
- соответствие общей архитектуре приложения;
- согласование контрактов API.

---

## Настройка Docker Compose и среды разработки

**Создан файл конфигурации Docker Compose**
- настройка сборки и запуска проекта в контейнерах.

**Развёрнуты два основных сервиса**
- контейнер с базой данных **PostgreSQL**;
- контейнер со средой разработки на **Python**.

**Обеспечено взаимодействие сервисов**
- настройка сетевого взаимодействия между приложением и БД;
- конфигурация переменных окружения для подключения к базе данных.

**Реализована единая среда разработки**
- все участники команды работают с актуальной БД;
- запуск проекта не зависит от локального окружения.

## Настройка пакетного менеджера Poetry

**Подключён и настроен Poetry**
- описание зависимостей в `pyproject.toml`;
- фиксация версий библиотек.

**Обеспечена воспроизводимость окружения**
- отсутствие конфликтов зависимостей;

**Интеграция Poetry в Docker-окружение**

- упрощение запуска проекта.
